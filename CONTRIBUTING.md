# Как участвовать

Репозитории Stone.BIM приватные: доступ выдаёт владелец организации. Внешние пул-реквесты не принимаются — сначала обсудите задачу в issue.

## Перед началом

- Прочитайте `README.md` репозитория, а если есть — `AGENTS.md` и `docs/`: там правила конкретного проекта, которые не выводятся из кода.
- Для задачи заведите issue по шаблону: версия, шаги, ожидаемый результат. Так видно контекст и воспроизводимость.

## Ветки и коммиты

- Основная ветка — `main`, история линейная.
- Один коммит — одна логически цельная мысль. Формат темы:

  ```
  <тип>: <Область> — <что и зачем>
  ```

  Тип — `feat`, `fix`, `refactor`, `docs`, `test`, `chore`. Тема — императив, до 72 символов, без точки в конце. В теле — «почему» и последствия, если из diff это не очевидно.
- Прямой push в `main` допустим для владельца; остальные изменения — через pull request.

## Перед коммитом

- Проект собирается без ошибок, тесты проходят (для `*.Core` — обязательно).
- В коммит не попадают `bin/`, `obj/`, `TestResults/`, логи, локальные настройки, сертификаты (`*.pfx`) и секреты (токены, ключи).
- Если проверка требует Revit, сети или Docker и не выполнялась — это явно написано в теле коммита.

## Pull request

- Один PR — одна задача, описание по шаблону.
- Изменение поведения или API сопровождается правкой документации.
- Ревью проводит владелец организации; замечания обсуждаются в PR.

## Документация

- Пользовательская документация — рядом с кодом (`docs-for-user` у плагинов).
- Внутренние правила, известные ограничения и gotcha — в `docs/` и `AGENTS.md` репозитория.
